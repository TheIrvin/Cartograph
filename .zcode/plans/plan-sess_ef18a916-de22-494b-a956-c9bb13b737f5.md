# Detailed TraceMap Implementation Plan — Deliverable

## What I'm creating (2 new files, original untouched)

1. **`tracemap-detailed-implementation-plan.md`** — the enhanced plan (~90–100 tracked features)
2. **`tracemap-feature-tracker.csv`** — machine-readable export of the master tracker (importable into Notion / Linear / GitHub Projects / Sheets for real status tracking)

The existing `tracemap-architecture-and-implementation-plan.md` stays as the strategy/reference doc. Strategy, phases, tech stack, and timelines are **not** changed — this adds granularity, sub-features, and tracking.

## Tracking system built into the doc

- **Feature IDs**: `F{phase}.{nn}` (e.g. `F0.23` = graph store schema). Referenced by dependencies.
- **Status legend**: ⬜ Not Started · 🟡 In Progress · 🔵 In Review · ✅ Done · 🚫 Blocked · ❌ Cut
- **Priority**: P0 launch-blocker · P1 should-have · P2 nice-to-have · P3 later
- **Effort**: XS <0.5d · S <1d · M 1–3d · L 3–7d · XL >1w
- **Master tracker table**: ID | Feature | Epic | Phase | Priority | Effort | Depends on | Status — one row per feature, at the top for at-a-glance tracking
- **Definition of Done** + doc-update conventions (changelog section at bottom)

## Document structure

1. **How to use this doc** — legends, ID scheme, update workflow
2. **Master Feature Tracker** — ~90 features in one table
3. **Phase 0 — MVP** (7 epics, ~52 features, full spec cards): Foundation/CI/Deploy · Repo Ingestion (URL validation, GitHub API client, shallow-clone fallback, size caps, async job queue + progress UI, error states) · AST Parsing & Graph Build (tree-sitter setup, TS/JS + Python extractors, symbol resolution, edge extraction, confidence scoring, framework route extraction, SQLite store, golden-file parser tests) · Diagram Viewer (React Flow canvas, auto-layout, node/edge design, confidence legend, click-to-highlight, GitHub deep links, tooltips, ⌘K search, large-graph performance) · Sharing & Distribution (permalinks, OG image generation, URL-hack redirect, browser extension, landing page) · Ask/Chat (context assembler, embeddings, streaming UI with node citations, prompt-injection guards, cost controls) · Caching & API hygiene (SHA-keyed cache, pre-warm, rate limits, health/metrics)
4. **Phase 1 — Trace Mode** (3 epics, ~11 features, full spec cards): Trace Engine (entry-point registry, forward trace path-finding, reverse impact analysis, animation engine, LLM path narration) · Public API & README badge · Launch kit & demo repos
5. **Phase 2 — Depth** (6 epics, ~14 features, lighter cards): GitHub OAuth + multi-repo workspaces, Kafka/RabbitMQ contract stitching, Neo4j migration, GitHub PR-diagram bot (graph diff between SHAs), Go/Java-Kotlin/Rust extractors, optional self-hosted model
6. **Phase 3 — Ecosystem** (5 epics, ~13 features, lighter cards): VS Code + JetBrains extensions, Docker Compose self-host bundle, SaaS tier (Stripe billing, private repos, teams, SSO), enterprise/compliance
7. **Cross-cutting specs**: column-level data model + indexes, v1 REST API surface table, confidence-scoring spec (solid vs dashed thresholds), testing strategy with parser-accuracy targets, performance budgets (sub-budgets behind the <30s TTFD goal), LLM/infra cost model, observability & alerts, security & abuse (SSRF, sandboxed parsing, prompt injection), Definition of Done
8. **Milestone gates** — measurable exit criteria per phase (tied to the original success metrics)
9. **Expanded risk register** — each risk gets trigger signal + contingency, not just mitigation

Each full spec card contains: user story, sub-tasks, acceptance criteria (verifiable), dependencies, and known risks/notes. Phase 0–1 get the deepest detail since that's what gets built first.
